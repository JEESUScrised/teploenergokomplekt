## 2. Прослушиваемые порты (релевантные)

| Адрес | Процесс | Комментарий |
|---|---|---|
| `0.0.0.0:3002` | `next-server` | **Пользовательский**, старый Next — цель устранения |
| `127.0.0.1:8080` и пр. | PID скрыт (`-`) | Службы провайдера — **не трогали** |
| `:80` / `:443` | nginx/Apache провайдера | Обслуживание сайта — **не трогали** |

Не путать: исходящие клиентские соединения ≠ LISTEN-порты. Проблема REG.RU относилась к программам, **слушающим** нестандартные TCP >1024; `next-server` на **3002** прямо попадал под этот критерий.

---

## 3. Что относилось к старому Next.js

1. Каталог приложения: `~/teploenergokomplekt` (`.next`, `node_modules`, `package.json`).  
2. `start-production.sh` — `npm run start -H 0.0.0.0 -p 3002`.  
3. `watchdog.sh` — каждые ~2 минуты проверял `127.0.0.1:3002` и перезапускал Next.  
4. Cron:  
   `*/2 * * * * /bin/bash …/teploenergokomplekt/watchdog.sh`  
5. Лог: `~/logs/teploenergokomplekt.log` (многократные старты + Wasm OOM).  
6. Архив `.bak-proxy/index.php` с `proxy_pass` на `:3002` — **не активен** в текущем `.htaccess` (сайт уже static).

---

## 4. Что было безопасно остановлено

После подтверждения static DocumentRoot:

1. Cron-строка watchdog **закомментирована** (`# DISABLED_STATIC_EXPORT …`).  
   Бэкап: `~/teploenergokomplekt/var/crontab.bak.*`  
2. `watchdog.sh` переименован в `watchdog.sh.off` (+ копия `watchdog.sh.disabled-static`).  
   Исходник **не удалён**.  
3. SIGTERM процессам именно с cmdline `npm run start … 3002` / `next-server` (без `pkill node` / `killall`).  
4. Порт **3002 закрыт**; повторная проверка через >2 мин — Next **не** поднялся.

Инструкция восстановления (если когда-либо понадобится Node, не для static):  
`~/teploenergokomplekt/var/HOW_TO_RESTORE_NEXT_WATCHDOG.txt`

**Не останавливались:** Apache/nginx/PHP провайдера, почта, `a-texgroup.com`, другие чужие сервисы.

## 8. Статус ограничения REG.RU

- Запрещённый пользовательский LISTEN на **3002 устранён**, автоперезапуск отключён.  
- С хоста выполнены пробные исходящие `curl` к внешним HTTPS (exit 0) — как **косвенный** признак, что исходящий канал с shell сейчас отвечает.  
- **Мы не утверждаем**, что тикет REG.RU / блокировка провайдера официально сняты: это делает только поддержка после их повторной проверки.

Рекомендуется отправить обращение (текст ниже) и дождаться ответа REG.RU.
